# Состояние тестовой сборки NOLA

Готовая игровая DLL пока не собрана. В этом репозитории находятся исходники
исправления передачи сохранений и сценарий Windows-сборки.

## Что проверено

На Windows Server 2022 с MSVC прошли все 16 сценариев нового теста `sxrecv`
и все 8 проверок существующего `sxreq`. Пропущенных проверок нет.

- Проверенный коммит: `78c1593cb3b63d0a74cc633beeae79bc45e159ac`.
- [Успешный запуск нативных тестов](https://github.com/ermolenkom986-lab/nola-coop-build/actions/runs/43754893662).
- Артефакт `native-test-logs` содержит `sxrecv.log` и `sxreq.log`.
- Та же обновлённая группа из 16 сценариев прошла в Wine 10.0.

Зелёный результат этого запуска относится только к тестам сетевого кода.
Полная сборка была явно отключена параметром `build_dll=false` и отображается
как `skipped`. Тестовая программа не является игровым модом.

## Что блокирует получение DLL

NOLA v1.4.2 использует RE-UE4SS
`5e627997bf265ae6fc89d23357543d8c8ac05a6f`. Его зависимость
`deps/first/Unreal` указывает на закрытый репозиторий
`Re-UE4SS/UEPseudo`, коммит `38e7171e9e8c4a871ff84765848f0290ca34a44e`.
При скачивании GitHub возвращает `Repository not found`.

[Запуск полной сборки с этой ошибкой](https://github.com/ermolenkom986-lab/nola-coop-build/actions/runs/43753694287).

Это требование самой системы сборки UE4SS. В её
[официальной инструкции](https://github.com/UE4SS-RE/RE-UE4SS/blob/5e627997bf265ae6fc89d23357543d8c8ac05a6f/README.md#build-instructions)
указано: "You will need your github account to be linked to an Epic games account
to pull the Unreal pseudo code submodule."

Официальный `zDEV-UE4SS_v3.0.1-1164-g5e627997.zip` также проверен:
он содержит UE4SS.dll и символы отладки, но не содержит заголовков `.h/.hpp`
и библиотек `.lib/.a`, необходимых для сборки NOLA.

## Как продолжить полную сборку

1. [Связать GitHub с Epic Games](https://www.unrealengine.com/en-US/ue-on-github)
   и принять приглашение Epic Games на GitHub.
2. Проверить, что [страница UEPseudo](https://github.com/Re-UE4SS/UEPseudo)
   открывается под этим аккаунтом.
3. Для GitHub Actions настроить repository secret `UE4SS_READ_TOKEN`:
   токен должен иметь разрешение читать эту закрытую зависимость.
   Встроенный `GITHUB_TOKEN` относится только к данному репозиторию и не получает
   этот доступ автоматически после привязки аккаунтов.
   Токен вводится непосредственно в GitHub, в Settings → Secrets and variables →
   Actions; отправлять его в чат, коммит или журнал не нужно.
4. Запустить Actions → Build patched NOLA for Windows → Run workflow с включённым
   параметром `build_dll`.

Сценарий сначала выполняет тесты, затем собирает `NolaNative` с
`S2X_RELEASE=ON` и проверяет встроенные таблицы. Только после успешного окончания
появится артефакт `NOLA-v1.4.2-save-transfer-dll` с настоящим `main.dll`, SHA256,
сведениями о сборке и журналами тестов.

После сборки нужно дополнительно проверить импорты DLL против UE4SS из официального
комплекта, упаковать обновление и протестировать игру на двух ПК. Причина исходного
вылета клиента через примерно 15 минут по журналу хоста не установлена.
